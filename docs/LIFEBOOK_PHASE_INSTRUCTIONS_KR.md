# MyDocuMgm(나의 생활북) 단계별 Codex 실행 지시문

## 1. 사용 방법

각 작업에서 다음 두 문서를 함께 제공한다.

1. `LIFEBOOK_COMMON_INSTRUCTION_KR.md`
2. 이 문서 또는 이 문서에서 현재 Phase 부분만 분리한 지시문

아래 프롬프트의 `[프로젝트 절대경로]`, `[자료 루트 절대경로]`, `[승인된 시작 HEAD]`는 실제 확정값으로 바꾼다. 확정되지 않았다면 Codex가 추정하지 않고 Phase 0의 사용자 결정 항목으로 보고해야 한다.

MyDocuMgm의 확정값은 프로젝트 `C:\EtcProject\MyDocuMgm`, DB `localhost\MSSQLSERVER01` / `MyDocuMgm`, 자료 루트 `C:\EtcProject\MyDocuMgm\data\MyDocuMgmData`이다. Codex 샌드박스는 Windows 인증 DB 연결을 수행하지 않으며, 생성된 SQL 적용과 DB 통합 검증은 사용자가 PowerShell 또는 SSMS에서 수행한다.

## Phase 2 — URL 수집 및 분석

### 진입 조건

### 목표

공개 URL에서 접근 가능한 정보만 수집하고, 근거 기반 요약·분류·태그 추천과 사용자 검토 흐름을 구현한다.

### 구현 범위

- URL 입력과 형식 검증
- 지원 사이트 식별
- 공개 원문 메타데이터 수집
- 본문, 화면 텍스트, 자막, 대표 댓글의 근거 분리
- AI 제목·요약·분류·태그 추천
- 신뢰도와 확인 필요 항목
- 중복 URL 경고
- `ImportJobs` 상태와 안전한 실패 기록
- 수동 붙여넣기·파일 선택 대체 입력
- 분석 검토 후 기존 콘텐츠 저장 흐름 연결

> Phase 2D 승인 보완(2026-08-21): `docs/MYDOCUMGM_PHASE2D_RECOMMENDATION_CONTRACT_KR.md`의 P2D-D01~D05가 추천 기반의 권위 계약이다. 이번 Phase 2D에서는 provider-agnostic 추천·결정 감사 기반만 구현하고 실제 외부 AI 연동, 자동 자막·댓글 수집 및 `ImportJobs`는 유보한다. `ExternalFetchAttempts`는 HTTP 요청별 시도 기록으로 유지하며 `ImportJobs`의 대체로 간주하지 않는다. 향후 전체 가져오기 orchestration이 별도 승인될 때 `ImportJobs`를 재검토한다.

> Phase 2D 수동 bridge 승인 보완(2026-08-21): 추천 실행은 `USER_MEDIATED_COPY_PASTE`로 제한한다. 제품은 현재 자료와 고정 분류 catalog로 검토·편집 가능한 프롬프트를 만들고, 사용자의 명시적 복사와 strict JSON 붙여넣기만 지원한다. 외부 AI 자동 전송·SDK·secret은 금지하며 raw prompt/response는 저장하지 않는다. import는 현재 자료 fingerprint와 근거 ID를 재검증하고, 검증된 추천만 기존 Phase 2D 감사 구조에 `MANUAL_COPY_PASTE`로 기록한다. import만으로 기존 Content를 변경하지 않으며 사용자의 항목별 결정과 최종 저장 계약을 유지한다.

### 제외

- 접근제한·로그인·비공개 콘텐츠 우회
- 사용자 쿠키 영구 저장

- 자동 게시

- 네트워크 중단
- 분석 시간 초과
- 일부 근거만 수집 성공
- AI 응답 실패 또는 잘못된 형식
- 같은 URL 재입력
- 사용자가 분석 취소

### 완료 조건

- 지원 조건과 미지원 조건이 UI에서 구분됨
- AI 결과를 사실로 자동 확정하지 않음

- 수동 대체 입력으로 저장 가능

원본 영상 영구 보관, 워터마크 제거, 자동 공개, 블로그 게시는 구현하지 마세요. 취소·오류·디스크 부족을 포함해 임시 파일 정리와 DB/파일 정합성을 검증하세요.

실제 브라우저에서 후보 선택과 순서 변경을 증거로 남기고, 공통 완료 보고 후 중단하세요.

## Phase 4 — 블로그 초안 및 내보내기

### 진입 조건

- Phase 3 PASS와 사용자 시각 승인
- 공개 콘텐츠·이미지 정책 승인

### 목표

검토 완료 콘텐츠를 블로그 게시에 적합한 텍스트·Markdown·HTML·이미지 묶음으로 생성하고 게시 이력을 관리한다.

### 구현 범위

- 분류별 초안 템플릿
- 미리보기와 사용자 수정
- 일반 텍스트·Markdown·HTML 생성
- 공개 허용 이미지 선별 및 순번 파일명
- 제목·본문·해시태그 복사
- 내보내기 폴더 생성
- 게시 채널·URL·제목·일시·상태 기록
- 재생성 시 기존 내보내기 덮어쓰기 방지

### 제외

- 네이버 블로그 자동 로그인·자동 클릭·자동 게시
- 사용자 확인 없는 외부 전송
- 비공개 이미지 포함

### 필수 검증

- 11개 분류별 최소 1개 템플릿 결과
- 특수문자와 한글 파일명
- HTML 이스케이프
- 공개 이미지 0개/여러 개
- 재생성·취소·디스크 오류
- 원본 콘텐츠 불변
- 게시 URL 기록과 수정

### 완료 조건

- 복사 가능한 미리보기
- 각 형식의 내용 일치
- 공개 가능 자산만 포함
- 원문 출처 유지
- 내보내기 실패가 원본을 변경하지 않음

### Codex 복사용 프롬프트

## Phase 5 — 백업·복원·안정화 및 인수

### 진입 조건

### 목표

DB와 파일을 동일 시점 단위로 백업하고 격리 복원 검증을 완료한 뒤 운영 가능한 사용 안내서를 제공한다.

### 구현 범위

- MSSQL 백업
- `data\MyDocuMgmData` 백업
- 백업 매니페스트와 해시
- 보존 정책
- 격리 DB·폴더 복원
- DB/파일 상호 참조 검증
- 손상·누락 백업 탐지
- 사용자 가이드
- 전체 회귀 및 브라우저 스모크

### 금지

- 검증 없이 운영 DB 덮어쓰기
- 사용자 승인 없는 오래된 백업 삭제
- 비밀정보를 백업 매니페스트에 기록

### 필수 검증

- 정상 백업과 격리 복원
- DB 백업 누락
- 이미지 묶음 누락
- 해시 불일치
- 공간 부족

- 보존 개수 초과

- Phase 1~4 전체 회귀

### 완료 조건

- 격리 복원 재현 성공
- 원본 운영 데이터 무변경
